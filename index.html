🐧 Servidor Samba no WSL2

Documentação completa para compartilhamento de arquivos entre Windows, Linux e rede local

✅ Versão 1.0 | Compatível com Windows 10/11 + WSL2

📋 Visão Geral

Este projeto configura um servidor Samba rodando dentro do WSL2 (Windows Subsystem for Linux) para compartilhar arquivos com a rede local. A solução contorna a limitação do Windows que utiliza a porta 445 (SMB) nativamente, desativando o serviço Windows e permitindo que o Samba do WSL2 assuma o controle.

🏗️ Arquitetura da Solução
Windows Host → WSL2 (com Samba) → Rede Local
Porta 445 bloqueada/desativada no Windows nativo
📁 Pasta Compartilhada
C:\compartilhado (Windows)
/mnt/c/compartilhado (WSL)
Acesso via: \\127.0.0.1\compartilhado

⚡ PERMISSÃO PARA EXECUTAR SCRIPTS NO POWERSHELL

⚠️ ATENÇÃO: Antes de executar qualquer script .ps1, é necessário liberar a política de execução de scripts no PowerShell.

🔧 Como liberar a execução de scripts:

1
Abra o PowerShell como Administrador (clique com botão direito no ícone e escolha "Executar como administrador")
2
Execute o comando abaixo para verificar a política atual:
Get-ExecutionPolicy
3
Libere a execução com a política RemoteSigned (recomendada para segurança):
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
4
Confirme com S (Sim) quando solicitado. Para verificar se funcionou:
Get-ExecutionPolicy
# Saída esperada: RemoteSigned
💡 Alternativa (execução avulsa sem alterar política):
powershell.exe -ExecutionPolicy Bypass -File ".\script.ps1"

📋 Níveis de Política de Execução:

PolíticaDescrição
RestrictedNenhum script é executado (padrão do Windows)
RemoteSignedScripts locais rodam; scripts baixados precisam de assinatura ✅ RECOMENDADO
AllSignedTodos os scripts precisam ser assinados digitalmente
BypassNada é bloqueado, sem avisos (usar com cautela)

🚀 Guia de Instalação Passo a Passo

Pré-requisitos

  • Windows 10/11 com WSL2 instalado e configurado
  • Distribuição Linux no WSL (Ubuntu recomendado)
  • Acesso Administrador no Windows
  • Conexão com a internet para instalação de pacotes

Passo 1: Configuração do Windows (PowerShell como Admin)

# Abra o PowerShell como Administrador e execute:
.\1-Setup-WSL-Samba.ps1
⚠️ Importante: Após executar este script, REINICIE O WINDOWS para garantir que as alterações nos drivers surtam efeito.

Passo 2: Configuração do Samba no WSL

# Torne o script executável
chmod +x 2-setup-samba.sh

# Execute (substitua 'seu_usuario' pelo seu nome de usuário Linux)
./2-setup-samba.sh seu_usuario

Passo 3: Criar a Tarefa de Inicialização Automática

# No Windows (PowerShell como Administrador)
.\Criar-Tarefa-Boot.ps1
📁 Importante: Certifique-se de que o arquivo Iniciar-Servidor.bat esteja no caminho C:\TI\scripts\

Passo 4: Validação da Instalação

# No WSL
chmod +x valida-deploy.sh
./valida-deploy.sh
✅ Resultado esperado: Todos os 6 testes devem retornar ✅

🛠️ Comandos Úteis do Dia a Dia

Iniciar/Parar o Servidor

# No WSL (como root ou com sudo)
sudo service smbd start
sudo service nmbd start
sudo service smbd stop
sudo service smbd restart

Verificar Status e Portas

sudo service smbd status
ss -tulpn | grep :445
sudo netstat -tulnp | grep :445
sudo tail -f /var/log/samba/log.smbd

Acessar o Compartilhamento

MétodoComando/Caminho
Explorador do Windows\\127.0.0.1\compartilhado
Mapear unidade de redenet use Z: \\127.0.0.1\compartilhado
De outro computador na rede\\[IP_DO_HOST_WINDOWS]\compartilhado

Gerenciar Usuários Samba

# Adicionar novo usuário Samba
sudo smbpasswd -a nome_usuario

# Listar usuários Samba
sudo pdbedit -L

# Remover usuário
sudo smbpasswd -x nome_usuario

# Alterar senha
sudo smbpasswd nome_usuario

🗑️ Funcionalidade da Lixeira (Recycle Bin)

O Samba está configurado com suporte à lixeira através do módulo vfs recycle.
  • Arquivos deletados são movidos para a pasta .lixeira dentro do compartilhamento
  • A estrutura de diretórios é preservada (keeptree = yes)
  • Versões de arquivos são mantidas (versions = yes)
  • Arquivos temporários (*.tmp, *.temp, ~$*) são excluídos permanentemente
# Para esvaziar a lixeira manualmente (no WSL)
rm -rf /mnt/c/compartilhado/.lixeira/*

🔄 Fluxo de Inicialização Completo

1
Windows Inicia
2
Tarefa Agendada "WSL_Samba_Startup" aguarda 20 segundos (após logon)
3
Executa Iniciar-Servidor.bat
4
.bat executa: wsl -u root -e bash -c "service smbd start && service nmbd start"
5
Samba inicia no WSL e assume a porta 445
6
.bat abre automaticamente o explorador em \\127.0.0.1\compartilhado

🔧 Solução de Problemas

❌ Porta 445 ainda ocupada pelo Windows

# PowerShell como Administrador
sc.exe config srvnet start= disabled
sc.exe config srv2 start= disabled
sc.exe stop srvnet
sc.exe stop srv2
# REINICIE O WINDOWS

❌ "Acesso negado" ao tentar acessar o compartilhamento

# Verifique se o usuário Samba existe
sudo pdbedit -L
# Reconfigure a senha
sudo smbpasswd -a seu_usuario
# Verifique as permissões da pasta
sudo chmod 777 /mnt/c/compartilhado

❌ Samba não inicia automaticamente após reinicializar

# Windows - verifique a tarefa agendada
Get-ScheduledTask -TaskName "WSL_Samba_Startup"
# Teste manual do .bat
C:\TI\scripts\Iniciar-Servidor.bat

❌ Não consigo acessar de outro computador na rede

# Verifique as regras de firewall
Get-NetFirewallRule -DisplayName "WSL Samba*" | Format-Table -AutoSize
# Teste a conectividade
Test-NetConnection -ComputerName [IP_DO_HOST] -Port 445

🛡️ Segurança e Boas Práticas

RecomendaçãoDescrição
FirewallApenas tráfego da rede local (LocalSubnet) é permitido
AutenticaçãoCompartilhamento exige autenticação SMB (guest ok = no)
Forçar usuárioTodos os acessos usam o mesmo usuário configurado
Protocolo mínimoSMB2 (SMB1 é inseguro e está desabilitado)
⚠️ Aviso: O Samba no WSL2 não deve ser exposto diretamente à internet. Use apenas em redes confiáveis.

🗑️ Remoção Completa da Configuração

# 1. Remover tarefa agendada (PowerShell Admin)
Unregister-ScheduledTask -TaskName "WSL_Samba_Startup" -Confirm:$false

# 2. Reabilitar SMB do Windows
Set-Service LanmanServer -StartupType Automatic
Start-Service LanmanServer
sc.exe config srvnet start= auto
sc.exe config srv2 start= auto

# 3. Remover regras de firewall
Get-NetFirewallRule -DisplayName "WSL Samba*" | Remove-NetFirewallRule

# 4. Remover .wslconfig
Remove-Item "$env:USERPROFILE\.wslconfig" -Force

# 5. No WSL - desinstalar Samba
sudo apt remove --purge samba samba-common-bin
sudo rm -rf /etc/samba
